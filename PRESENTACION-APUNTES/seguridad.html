/admin/** ROLE_ADMIN Solo administrador global
/centro-admin/** ROLE_ADMIN_CENTRO Admin de centro asignado
/profe/**, /tutor/** ROLE_PROFESOR Profesor

/snap-admin/** denyAll es una regla defensiva para evitar que si se reinstala accidentalmente la dependencia snap-admin (que fue eliminada), el panel quede expuesto.

Doble capa de autorización

Las rutas de SecurityConfig son la primera barrera. La segunda son las anotaciones @PreAuthorize en los controladores: 

@Controller
@PreAuthorize("hasRole('ADMIN')")
public class AdminController { ... }

@Controller
@PreAuthorize("hasRole('PROFESOR')")
public class ProfeController { ... }
Ambas capas son independientes. Un atacante que eluda una sigue bloqueado por la otra.

Las cabeceras "manual" se añaden en SecurityConfig. Las "default" las añade Spring Security 6 automáticamente sin configuración adicional.

CSRF

Habilitado por defecto para todos los formularios HTML. Thymeleaf integra automáticamente el token CSRF en los formularios con th:action. Para los endpoints de la API Swagger (/v3/api-docs/**) el CSRF está deshabilitado ya que son stateless.

Gestión de sesión

Session Fixation

changeSessionId() al autenticar. Nuevo ID en cada login.

Sesiones concurrentes

maximumSessions(1). Segunda sesión expira la primera. URL: /login?expired.

Timeout

30 minutos de inactividad (server.servlet.session.timeout=30m).

Cookie

HttpOnly=true, SameSite=strict siempre. Secure=true solo en perfil prod.

Almacenamiento

Spring Session JDBC: tabla SPRING_SESSION en PostgreSQL. Sobrevive reinicios.

Rate limiting (Bucket4j)

// LoginRateLimitFilter se inserta ANTES de UsernamePasswordAuthenticationFilter
http.addFilterBefore(loginRateLimitFilter,
    UsernamePasswordAuthenticationFilter.class);
Límite: 10 intentos por IP cada 15 minutos. El intento 11 devuelve HTTP 429. Algoritmo Token Bucket (Bucket4j). Protege contra ataques de fuerza bruta.

Validación de entradas

  • Todos los DTOs usan Java records con anotaciones Bean Validation (@NotBlank, @Size, @Email, etc.).
  • Los controladores usan @Valid + BindingResult para capturar errores de validación.
  • Las contraseñas en formularios de creación usan @ValidPassword (anotación personalizada en domain/validation/).
  • Las plantillas Thymeleaf usan siempre th:text (nunca th:utext) para datos de usuario, previniendo XSS.

Preguntas frecuentes

¿Por qué hay dos capas de autorización (URL + @PreAuthorize)?

Defensa en profundidad. Las reglas de URL en SecurityConfig son la primera barrera. Si por algún error de configuración fallara, @PreAuthorize en el controlador sigue bloqueando el acceso. Son independientes.

¿Qué es Content-Security-Policy y por qué importa?

Es una cabecera HTTP que indica al navegador qué recursos puede cargar. Con default-src 'self' y frame-ancestors 'none', se evita que la app cargue scripts de terceros (XSS) y que sea embebida en iframes (clickjacking).

¿Qué version de Spring Security usa Schooledule?

Spring Security 6 (incluido con Spring Boot 3.3.5). Usa el nuevo estilo de configuración con lambdas en lugar del deprecated WebSecurityConfigurerAdapter.

¿Por qué se bloquea /snap-admin/** si la dependencia ya fue eliminada?

Es defensa contra reinstalaciones accidentales. Si alguien añadiera de nuevo snap-admin al pom.xml, el panel CRUD quedaría expuesto sin autenticación de Schooledule. La regla denyAll en primer lugar del authorizeHttpRequests garantiza que nunca sea accesible.
