Portal Profesor

El profesor gestiona su cuaderno de notas por impartición y, si es tutor, accede a los grupos asignados.

Datos clave

Rol requerido
ROLE_PROFESOR
URLs
/profe/**

+ /tutor/** (mismo rol)

Controladores
ProfeController

+ TutorController

Flujo del cuaderno de notas (3 pasos)

1. Dashboard Selecciona centro → 2. Imparticiones Ver asignaturas del centro → 3. Cuaderno Alumnos + notas por CE
Ruta Tipo Descripción
/profe/dashboard GET Seleccionar centro asignado
/profe/centro/{centroId}/asignaturas GET Lista de imparticiones del profesor en ese centro
/profe/imparticion/{id}/alumnos GET Cuaderno de notas: lista de alumnos matriculados
/profe/api/matricula/{id}/notas GET JSON Carga las notas actuales de un alumno (por CE)
/profe/api/matricula/{id}/notas POST JSON Guarda/actualiza notas. Dispara la auditoría.
/profe/imparticion/{id}/items POST Crear un ítem evaluable (examen, práctica, etc.)
/profe/items/{id}/eliminar POST Eliminar un ítem evaluable

Tipos de ítems evaluables

Al crear un ItemEvaluable, el profesor elige el tipo mediante el enum tipo_actividad:

EXAMEN

Prueba escrita o test formal.

PRACTICA

Trabajo práctico, proyecto o laboratorio.

RECUPERACION

Examen de recuperación para alumnos suspensos.

ACTITUD

Evaluación de comportamiento y participación.

Auditoría de notas

Cada vez que un profesor guarda una nota se activa la cadena de auditoría:

1. TeacherDashboardService → 2. set_config() → 3. UPDATE calificaciones → 4. Trigger PL/pgSQL → 5. auditoria_notas
set_config: Antes de persistir la nota, el servicio ejecuta la query nativa:
SELECT set_config('app.usuario_actual', :email, true)
Esto inyecta el email del profesor en la sesión PostgreSQL para que el trigger sepa quién hizo el cambio.
El trigger trigger_auditoria_notas se dispara AFTER UPDATE en calificaciones. Llama a registrar_cambio_nota() que inserta en auditoria_notas: valor_anterior, valor_nuevo, usuario_responsable, fecha_cambio.

Portal Tutor (/tutor/**)

El tutor es un profesor asignado como tutor de un grupo (grupos.tutor_id FK → usuarios.id). No es un rol separado, usa ROLE_PROFESOR.

Regla: Un tutor puede ver todos los grupos donde figure como tutor. Para editar notas de una impartición concreta, además debe ser el profesor asignado a esa impartición (imparticiones.profesor_id).

Preguntas frecuentes

¿Cómo sabe la base de datos quién modificó una nota?

El servicio inyecta el email del usuario autenticado en la sesión PostgreSQL con set_config('app.usuario_actual', email, true). El trigger PL/pgSQL lee esa variable con current_setting('app.usuario_actual') y la guarda en auditoria_notas.usuario_responsable.

¿Puede un profesor ver/editar notas de otro profesor?

No. El servicio valida que la imparticion.profesor_id coincida con el usuario autenticado antes de permitir la modificación de notas. Aplicación del principio de propiedad de datos.

¿Qué diferencia hay entre /profe/** y /tutor/**?

Ambos requieren ROLE_PROFESOR. /profe/** es el cuaderno de notas normal. /tutor/** da acceso a los grupos donde el profesor figura como tutor (grupos.tutor_id), que incluye ver notas en modo lectura y, si también es el profesor de la impartición, editarlas.

¿Qué tipos de actividades puede crear un profesor?

EXAMEN, PRACTICA, RECUPERACION y ACTITUD. Son los valores del enum tipo_actividad definido en PostgreSQL.
