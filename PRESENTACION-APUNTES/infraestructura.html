Infraestructura y Despliegue

Dockerfile multi-stage, Docker Compose (dev y prod), Flyway, perfiles de Spring y configuración de la base de datos.

Dockerfile multi-stage

Ubicación: infraestructura/Dockerfile. Tiene 3 etapas:

Stage 1: builder

Imagen: maven:3.9.9-eclipse-temurin-21-alpine

  • Copia pom.xml y ejecuta mvn dependency:go-offline (caché de dependencias)
  • Copia src/ y ejecuta mvn spotless:apply clean package -DskipTests

Stage 1.5: test

Hereda del builder. CMD: mvn verify -DskipTests=false -B

Usado en CI con docker build --target=test.

Stage 2: runtime

Imagen: eclipse-temurin:21-jre-alpine

  • Usuario no-root: spring:spring
  • Puerto expuesto: 8080
  • Healthcheck: wget http://localhost:8080/login
  • JVM: -XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0
Seguridad: El contenedor de runtime usa un usuario no privilegiado (spring:spring). El proceso Java nunca corre como root.

Migraciones Flyway

Flyway aplica automáticamente los scripts SQL al arrancar la app. Solo hay 2 migraciones:

V1__schema_definitivo.sql

Schema completo: todas las tablas, enums, índices, trigger de auditoría y tablas de Spring Session.

V2__seeds_desarrollo.sql

Datos de prueba: usuarios admin@tfg.com, juan@tfg.com, ana@tfg.com, pedro@tfg.com. Contraseña: 1234 (BCrypt).

Aviso producción: V2 incluye usuarios de desarrollo. En un despliegue real hay que crear un V2 vacío o con datos reales antes de usar en producción.

Preguntas frecuentes

¿Por qué se usa un Dockerfile multi-stage?

Para separar la etapa de compilación (imagen pesada con Maven y JDK) de la de ejecución (imagen ligera con solo JRE). La imagen final es mucho más pequeña y no contiene herramientas de compilación innecesarias.

¿Qué diferencia hay entre el Docker Compose de dev y prod?

Dev tiene 4 servicios: postgres, pgAdmin, app y SonarQube. Prod tiene solo 2: postgres y app. Prod no tiene herramientas de análisis ni administración de base de datos.

¿Qué hace el flag -XX:MaxRAMPercentage=75.0 de la JVM?

Le dice a la JVM que use hasta el 75% de la RAM disponible en el contenedor para el heap. Con -XX:+UseContainerSupport, la JVM detecta correctamente los límites de memoria del contenedor en lugar de ver toda la RAM del host.

¿Cuántas migraciones Flyway hay?

Dos: V1__schema_definitivo.sql (esquema completo) y V2__seeds_desarrollo.sql (datos de prueba). Flyway las aplica en orden al arrancar la aplicación si no están ya aplicadas.
